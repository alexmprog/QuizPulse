# Contracts

QuizPulse has two contracts with different sources of truth.

| Contract | Source of truth | Consumers |
|---|---|---|
| REST (`/api/v1`, `/healthz`) | [`contracts/openapi.yaml`](../contracts/openapi.yaml), OpenAPI 3.1 | backend request validation, generated web types |
| Socket.io namespace `/game` | [`packages/protocol`](../packages/protocol) (TypeScript and zod) | backend, web |

[`contracts/asyncapi.yaml`](../contracts/asyncapi.yaml) (AsyncAPI 3.0) is documentation of the socket protocol for a future
Compose Multiplatform client that cannot import the TypeScript package. It is not the source of truth: a test
(`packages/protocol/test/asyncapi.test.ts`) only guarantees that its message names equal `CLIENT_EVENTS` and
`SERVER_EVENTS`. Payloads and acks are maintained by hand, so update it together with `packages/protocol`.

## REST conventions

- Prefix `/api/v1`; `GET /healthz` is outside it.
- Session is the HttpOnly cookie `qp_session`. State-changing requests also send the `X-CSRF-Token` header with the
  token from `GET /api/v1/auth/csrf`. The token is bound to the session: login and register rotate it (the new token
  is returned in the `X-CSRF-Token` response header), and after logout the client must call `GET /api/v1/auth/csrf`
  again before its next state-changing request.
- Errors are `{ "code": ErrorCode }` (plus `gameId` for `ACTIVE_GAME_EXISTS`); the web localizes the text. The
  `ErrorCode` enum in OpenAPI mirrors `ERROR_CODES` in the protocol package.
- Validation limits in `QuizInput` mirror `packages/protocol/src/limits.ts`. The cross-field rules per question type
  (options count, `correctOption`, numeric fields) are described in prose and enforced by `quizInputSchema`.
- `GET /api/v1/images/{id}` is public: the UUID is the capability, so players can load question images.

## Generated types

`packages/api-types/src/generated.ts` is generated by `openapi-typescript` and must never be edited by hand. It
exports `paths` and `components`.

```sh
pnpm gen              # regenerate after changing contracts/openapi.yaml
pnpm contracts:check  # redocly lint, asyncapi validate, generated.ts freshness
pnpm check            # everything, including contracts:check
```

The freshness check generates into a temporary file and compares it with `cmp`, so a stale `generated.ts` fails
`pnpm check`. Generated types do not validate remote JSON at runtime.
